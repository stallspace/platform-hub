# Stallspace — Hardening Changes (7 July 2026)

Summary of the fixes made in this pass. Grouped by the issues from the review.

## 1. Payment credentials secured (critical)
- New `src/lib/crypto/secrets.ts` — AES encryption of vendor credentials at rest (`PAYMENT_ENCRYPTION_KEY`).
- New `src/lib/supabase/admin.ts` — service-role client for trusted server routes.
- New `POST /api/vendor/payment-config` — encrypts on save; `GET` returns masked values.
- New `POST /api/checkout/initiate` — builds gateway redirects server-side; secrets never sent to the browser.
- New `POST /api/checkout/payment-method` — returns only provider/configured (non-secret).
- Gateway logic moved to server libs: `payments/payfast.ts`, `payments/yoco.ts`, `payments/peach.ts` (Ozow lib already server-side).
- `checkout/page.tsx` and `vendor/payments/page.tsx` + `PaymentsClient.tsx` refactored to never touch secrets.
- Old `/api/checkout/yoco` and `/api/checkout/peach` now return `410 Gone`.

## 2. Server-side payment verification (critical)
- New `POST /api/checkout/verify` — confirms Yoco/Peach payments against the gateway API before marking an order paid.
- `checkout/success/page.tsx` no longer sets order status from the browser; it calls verify.
- `api/orders/notify` PayFast/Ozow webhooks now set the valid `confirmed` status (was an invalid `paid`), guarded to a single transition.
- Order totals recomputed server-side in `POST /api/orders` — client prices are ignored (price-tamper fix).

## 3. RLS & schema (critical)
- New `supabase/migrations/002_security_hardening.sql` (idempotent):
  - Reconciles `customer_addresses`, `customer_favourites`, `vendor_store_settings` into version control.
  - Locks down `vendor_payment_configs` (owner-only, no public read).
  - Adds admin/vendor policies for orders, reviews, enquiries, categories, homepage content, analytics, documents, subscription events.
  - Adds `enforce_product_limit()` trigger (20 / 50 / unlimited by plan).

## 4. Admin-managed billing
- `VendorDetailClient.tsx` — admin can set plan/status/next-billing and record a payment (logs `subscription_events`, advances billing one month).
- Prices/limits aligned to R250/R500/R1000 and 20/50/unlimited.

## 5. Endpoint hardening & cleanup
- `escapeHtml` added and applied across all email templates and the enquiry-reply and order emails (XSS/injection fix).
- `api/track` — removed debug logging, added validation.
- `api/reviews` — validation, length caps, existence checks, and rate limiting (`lib/utils/rate-limit.ts`).
- `api/notifications/send` — vendor/subscription events now require an authenticated admin.
- `lib/notifications/create.ts` — uses service role so admin-to-vendor notifications aren't blocked by RLS.
- Repo cleanup: untracked `nohup.out`, `*.bak`, `*.old`, `.DS_Store`; `.gitignore` updated.
- Removed the deprecated duplicate `react-query` v3 dependency.

## 6. Build quality
- Added `"target": "ES2020"` to `tsconfig.json` — the project now type-checks cleanly (`npm run type-check` previously never worked).
- Fixed pre-existing type errors (Supabase cookie typings, to-one join typings, missing `is_featured` in a select).
- Added `tests/` (13 unit tests) and an `npm test` script.

## New environment variables
- `PAYMENT_ENCRYPTION_KEY` (server-only, ≥32 chars) — required.
- `OZOW_ENV` — `test`/`live`.

See `STALLSPACE_SYSTEM_DOCUMENTATION.md` and `STALLSPACE_TEST_PACK.md` for full detail.
